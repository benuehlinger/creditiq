# Handing CreditIQ to another machine

The repository is the single source of truth. One clone the first time, one
pull for every update after that.

## First time on a new machine

```bash
git clone https://github.com/benuehlinger/creditiq.git
cd creditiq
make setup      # venv + dependencies, about a minute
make dev        # backend :8000, frontend :5173
```

Open <http://localhost:5173>. The app detects that the machine has no data
and offers **Generate the synthetic data**: one button, 29 tracked steps
with a step counter and a clock, a few minutes, entirely local. When it
finishes the app reloads itself into the workspace.

Prerequisites: Python 3.12, Node 18+, [uv](https://docs.astral.sh/uv/),
GNU make. No network is needed at run time and no API keys exist.

## Getting updates

```bash
cd creditiq
git pull
```

Then restart `make dev`. If the pull changed `backend/creditiq/data/`, the
app will tell you the saved versions are on a stale panel; run `make data`
to regenerate (deterministic — same seeds, same bytes).

## Lazy vs warm

- `make dev` starts instantly and stays light. The first click on each
  surface computes once (a few seconds) and is cached afterwards, in memory
  and on disk (`data/cache/`), so a restart does not recompute.
- `make demo` pre-warms everything at boot for instant first clicks. It
  loads and profiles all three books: roughly **9 GB of memory**. On a
  machine without that much free memory it will swap and the app will
  appear frozen — this is why lazy is the default.

## If something looks wrong

| Symptom | Cause and fix |
|---|---|
| Frontend stuck on loading skeletons at boot | You are on an old build that warmed caches eagerly. `git pull`; warm-up is now opt-in. |
| "stale data" flags on saved versions | The panel was rebuilt under them. The specifications still replay; the stored metrics describe the old panel. Open and refit to refresh, or delete the version. |
| A fit or projection is slow the first time | That is the lazy trade: it computes once, then serves from `data/cache/` even across restarts. |
| Port 8000 or 5173 already in use | Another instance is running; stop it or change the port in the Makefile. |

## What is safe to delete

`data/cache/` (derived results), `data/synthetic/*.parquet` (regenerated by
the button or `make data`), `frontend/node_modules/` and `backend/.venv`
(recreated by `make setup`). Saved model versions live in `versions/` and
are NOT derived — deleting them deletes work.
